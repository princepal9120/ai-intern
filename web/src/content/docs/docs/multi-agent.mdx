AI Intern organizes automated software engineering tasks across four specialized roles. Instead of running a single monolithic model prompt with unrestricted permissions, tasks flow through bounded agents with clear responsibilities and explicit approval gates.

## The Agent Hierarchy

<CardGrid>
  <Card title="1. Captain (Orchestrator)" icon="star">
    Lives in a Cloudflare Durable Object. Ingests webhooks from Slack, Jira, or GitHub, manages conversation state, coordinates child agents, and enforces approval gates.
  </Card>
  <Card title="2. Planner" icon="document">
    Inspects repository structure, identifies relevant files, drafts task steps, and produces an execution plan before any code is modified.
  </Card>
  <Card title="3. Executor (Claude Code / OpenCode)" icon="laptop">
    Runs inside an isolated Cloudflare Sandbox gVisor micro-container. Clones the target branch, writes code, and executes test suites.
  </Card>
  <Card title="4. Reviewer" icon="magnifier">
    Audits the generated git diff, inspects test execution output, and checks for security vulnerabilities or unintended changes before PR creation.
  </Card>
</CardGrid>

## Lifecycle of a Task

<Steps>

1. #### Ingestion & Context Gathering

   A developer mentions `@AI Intern` in Slack, updates a Jira ticket, or triggers a GitHub issue webhook. The Captain extracts repository coordinates, issue context, and target branch.

2. #### Planning & Command Formulation

   The Planner analyzes the repository layout and drafts the delegation proposal, including the target files and planned terminal commands.

3. #### Approval Gating

   The Captain pauses execution and sends an interactive approval request to Slack and the Web Dashboard. Execution halts until human sign-off is recorded.

4. #### Sandboxed Execution

   Upon approval, the Captain spins up an ephemeral Cloudflare Sandbox container running Claude Code or OpenCode. The container executes in a hardened gVisor kernel with strictly bounded network egress.

5. #### Review & Verification

   The container runs unit and integration tests. The Reviewer agent audits the git diff against security policies and test logs.

6. #### Pull Request Publication

   If verification passes, the Captain pushes a branch and opens a GitHub Pull Request with full context, test logs, and summary notes.

</Steps>

## Isolation & Security Boundaries

Each agent executes within a dedicated boundary appropriate for its responsibilities:

| Agent | Runtime Environment | Permissions | Egress Scope |
| :--- | :--- | :--- | :--- |
| **Captain** | Cloudflare Workers & Durable Objects | Read/write task state, issue webhook calls | Webhook endpoints, AI Gateway |
| **Planner** | Workers AI Inference | Stateless model prompt | No network access |
| **Executor** | Cloudflare Sandbox (gVisor Container) | Filesystem writes, shell commands, test runs | Scoped strictly to target GitHub repo & provider API |
| **Reviewer** | Cloudflare Workers Runtime | Read-only diff analysis & PR creation | GitHub REST API |

## State Management

The Captain agent uses Cloudflare Durable Objects to store session history, approval decisions, and execution transcripts. Ephemeral container filesystems are wiped after each run, ensuring no state leaks between tasks.
